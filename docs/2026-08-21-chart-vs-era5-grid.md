# 天気図画像とERA5格子の比較 — 到達点と、未解決のこと

2026-08-21。ブランチ `claude/val-split-and-calibration`。

このファイルは、後から読む人(数か月後の自分を含む)が、会話のログを持たない状態で
同じ地点から再開できるように書いている。数字は再現に必要な条件つきで載せる。

> **数字は `data/labels_v2.csv` で測ったもの**(runs/v2_chart・runs/v2_grid)。
> `labels.csv` で測った旧版との違いは「ラベルを直して何が変わったか」に書いた。

## 問い

天気図の画像と、その元になっているERA5の気圧場。気圧配置の分類にはどちらが有効か。
出発点の仮説は「格子は天気図の元データなのだから上位互換のはず」だった。

**この仮説は否定された。** ただしラベルによっては逆になる。

## 結論

leave-one-year-out 交差検証(2023/2024/2025)、macro F1。

| 入力 | macro F1 | 自明な予測との差 | fold間の標準偏差 |
|---|---|---|---|
| 天気図画像 | 0.626 | +0.359 | 0.006 |
| ERA5格子 | 0.512 | +0.245 | 0.023 |
| 両方(確率を混ぜる) | **0.640** | **+0.374** | 0.022 |

**単独では天気図が勝つが、両方使うのが最良**(「組み合わせ」を参照)。

「自明な予測」は、全部を陽性と答えるだけで得られる macro F1 (この10ラベルでは0.258)。
**macro F1 の絶対値だけを見てはいけない。** 出現率pのラベルは何もしなくても 2p/(1+p) を取る。

前線2ラベル(front_passage / stationary_front)は格子に含まれない情報なので、除いても比べた。

| 入力 | 全ラベル | 前線2つを除外 |
|---|---|---|
| 天気図 | +0.359 | +0.357 |
| ERA5格子 | +0.245 | +0.268 |
| 差 | −0.114 | **−0.089**(全foldで同符号) |

前線で説明できるのは0.025、全体の2割ほど。**天気図の優位の大半は前線記号ではない。**
天気図は前線を除くと0.626→0.599と落ちるが、格子はほぼ動かない(0.512→0.510)。

除外後の基準も同じ8ラベルで取り直している(前線は出現率が高く、停滞前線は3割あるので、
片側だけ10ラベルの基準と比べると上積みを過大評価する)。

### ラベルごとには、得意分野が分かれる

| ラベル | 天気図 | ERA5格子 |
|---|---|---|
| 台風 | 0.766 | 0.478 |
| 日本海低気圧 | 0.645 | 0.437 |
| 南岸低気圧 | 0.597 | 0.489 |
| 前線通過 | 0.718 | 0.430 |
| 移動性高気圧 | 0.721 | 0.696 |
| 西高東低 | 0.754 | 0.723 |
| **オホーツク海高気圧** | **0.319** | **0.470** |

低気圧・台風・前線は天気図の圧勝、大規模な高気圧と冬型は互角、オホーツク海高気圧
だけ格子が優る。**この逆転は3つのfoldすべてで起きる**(格子 0.50/0.43/0.48 に対し
天気図 0.30/0.33/0.33)ので、ばらつきの範囲ではない。

オホーツク海高気圧は「オホーツク海にある」という位置が定義そのもので、等圧線の形に
特徴が乏しい。Grad-CAMでも、天気図モデルは高気圧本体ではなく下流の等圧線を見ていた。
格子側は座標チャンネル(`--coordconv`)で位置を直接参照できる。

## 測り方の欠陥を3つ直した。直す前の数字は使えない

**この3つを直す前に出た数値は、すべて信用できない。** 特にERA5格子側は数字が
0.473 → 0.234 と激変した(天気図側は 0.613 → 0.619 でほぼ変わらなかった)。

### 1. モデル選択の指標が、報告する指標と別物だった

ベストエポックの判定に閾値0.5固定の macro F1 を使い、最終評価では閾値を最適化していた。
pos_weight で陽性寄りに学習させる以上、初期エポックは何でも0.5を超えて高いF1が出て、
学習が進んで予測が鋭くなるほど0.5超えが減る。**エポック1が最高値を取り、patienceで
エポック9に打ち切られ、ほぼ未学習の重みが保存されていた**(3つのfoldすべてで発生)。

閾値に依存しない macro AP で選ぶように変更(`--select-metric macro_ap`、既定)。

### 2. 自明な予測との比較をしていなかった

macro F1 0.250 を「低いが学習はできている」と読んでいたが、自明な予測は0.258。
**下回っていた。** `src/evaluate.py` の `trivial_macro_f1` が毎回出力するようにした。

### 3. 検証データが8〜12月に偏っている(影響は残るが、当初より小さい)

`--val-mode tail` は学習期間の末尾を検証に回すため、検証が5か月・テストが12か月になる。
この偏りは今日3回、別々の形で問題を起こした。

- 224格子でval_lossが2.9〜121の間を暴れた
- val_apがエポック24を最良としたが、テストではエポック1の重みのほうが良かった
- 天気図と格子を混ぜる重みの選択が破綻した(下記)

`--val-mode spread` が用意されているが、まだこれで取り直していない。

ただし okhotsk_high については、ラベルを直して陽性が188件(8.7%)になったことで
検証データにも現れるようになった(`scripts/preflight` が警告を出さない)。
上の3件はいずれも陽性85件の頃の観測なので、いまどれだけ残っているかは未確認。

## ERA5格子側は、モデルを作り直した

EfficientNet-B0 をそのまま流用すると、正しく測れば自明な予測を下回る(0.234)。
`--arch small_cnn`(`src/model.py` の `SmallCNN`)に替え、`--coordconv` を足して 0.497。

**当初これを容量の問題と診断したが、誤りだった。** 幅を振ると性能は6万から385万
パラメータまで単調に上がる。EfficientNet-B0 とほぼ同じ385万パラメータの浅いネットが
0.497、EfficientNetが0.234。**容量を揃えても結果が正反対なので、効いているのは構造。**

| 幅 | パラメータ | macro F1 |
|---|---|---|
| 16 32 64 64 | 61k | 0.386 |
| 32 64 128 128 | 242k | 0.424 |
| 48 96 192 192 | 543k | 0.441 |
| 64 128 256 256 | 964k | 0.452 |
| 96 192 384 384 | 2.17M | 0.481 |
| **128 256 512 512** (既定) | **3.85M** | **0.497** |
| 160 320 640 640 | 6.01M | 0.502 (ばらつきが増える) |
| EfficientNet-B0 | 4.02M | 0.234 |

EfficientNet側の何が悪いのかは**切り分けていない**。候補は、深さ(16ブロック対4段)、
気圧場に転移しないImageNet重みからの出発、2チャンネル入力では意味をなさないSEブロック。

なお格子の解像度は、既定の128がERA5の元データ(181×221点)より粗い。224に上げると
むしろ悪化したが、それは当時EfficientNetを使っていたためで、SmallCNNでは試していない。

## 組み合わせ

### 両モデルの確率を混ぜる — labels_v2 では効く(`scripts/ensemble_chart_grid.py`)

| | macro F1 | 自明な予測比 | fold間の標準偏差 |
|---|---|---|---|
| 天気図のみ | 0.626 | +0.359 | 0.006 |
| ERA5格子のみ | 0.512 | +0.245 | 0.023 |
| 混合(一律の重み) | 0.636 | +0.369 | 0.040 |
| **混合(ラベルごとの重み)** | **0.640** | **+0.374** | 0.022 |

天気図単独を+0.014上回る(fold別 +0.016 / +0.031 / -0.002)。一律の重みでも0.636まで
来るが、1つのfoldで天気図を下回りばらつきが大きい。**重みはラベルごとに決めること。**

重みの選ばれ方が、そのまま得意分野の対比になっている(0=天気図のみ / 1=格子のみ)。

| ラベル | 天気図 | 格子 | 重み | 混合 |
|---|---|---|---|---|
| オホーツク海高気圧 | 0.319 | 0.470 | **0.93** | 0.474 |
| 台風 | 0.766 | 0.478 | **0.02** | 0.753 |
| 停滞前線 | 0.749 | 0.608 | 0.05 | 0.720 |
| 二つ玉低気圧 | 0.433 | 0.338 | 0.22 | **0.484** |

二つ玉低気圧の+0.051が最大の伸び。どちらも単独では低い(0.433 / 0.338)のに混ぜると
0.484になるので、両者は違う誤りをしていて打ち消し合っている。

学習済みの重みを使うので再学習は不要。重みと閾値はどちらも検証データで決め、
テストには一度も触れずに適用する。

#### labels.csv では効かなかった

同じ手順を旧ラベルで走らせたときは、混合(ラベルごと)が0.617で天気図単独の0.619に
届かなかった。okhotsk_highの重みがfoldごとに0.20/0.75/0.20とばらついたのが原因で、
陽性85件では8〜12月の検証データにこの型がほとんど現れず、**重みを選ぶ材料が無かった**。

陽性が199件になって検証にも現れるようになると、重みは0.85/0.95/1.00で安定する。
`scripts/preflight` が「検証データに1件も現れないラベル」を警告するのは、この失敗が
理由。

**特徴ベクトルの連結は採らない。** `scripts/ensemble_era5.py` に記録があるとおり、
ERA5の数値をCNNの特徴に連結したときは次元比(1280対17)のせいで信号が埋もれた。

## うまくいかなかったこと

### ImageNetの事前学習を格子に転用する

最初の畳み込みだけ作り直して残りを引き継ぐ実装は入れた(`_adapt_first_conv`)。
EfficientNetでは効果がなかった(0.473→0.473)。滑らかな気圧場には自然画像の

**取り直した。このページの数字は `labels_v2.csv` のもの。** `labels_v2.csv` と

#### ラベルを直して何が変わったか

okhotsk_high の陽性が 85 → 199(同じ2432行)。

| | labels.csv | labels_v2.csv |
|---|---|---|
| 天気図 全体 | 0.619 | 0.626 |
| ERA5格子 全体 | 0.497 | 0.512 |
| 天気図 okhotsk_high | 0.131 ± 0.081 | **0.319 ± 0.019** |
| ERA5格子 okhotsk_high | 0.345 ± 0.150 | **0.470 ± 0.033** |

天気図のokhotsk_highは2.4倍になった。**0.131という値はモデルの能力ではなく、
ラベルの欠落を測っていた。** fold間の標準偏差も両方とも4分の1以下になり、
初めて報告できる数字になった。

一方で全体の差(0.122 → 0.114)と、okhotsk_highで格子が上回るという関係は変わらない。
**ラベルの不備で説明できたのは差の一部だけで、残りは実際の性能差。**

### 2. オホーツク海高気圧のラベルには、それでも見落としが残りうる

`scripts/label_tool.py` の `positives_union` は「一度でも陽性とした」天気図だけを
見直しの対象にする。**一貫して見落とされてきた事例は永久に陰性のまま。**
陽性23〜36件という数は、実際の出現頻度より少ない可能性がある。

### 3. 希少ラベルは、平均を報告できる状態にない

出現数23〜36件のラベルは、最良の構成でもfold間で倍以上ばらつく。

ラベルを直したことで okhotsk_high は安定した(格子 0.50/0.43/0.48)。残るのは
futatsudama_low で、天気図 0.433 ± 0.135(0.28 / 0.49 / 0.53)と10ラベル中もっとも
ばらつく。陽性92件。

**このラベルは見直しを受けていない。** okhotsk_high が85→199で挙動が一変した前例が
あるので、まずラベルの品質を疑うこと(`scripts/label_tool.py` の盲検レビューが使える)。
2つの低気圧の位置関係で決まる型なので、判定基準は揺れやすいはず。

ラベルが妥当だと確認できてなお不安定なら、そこから先はデータ量の問題。

`awg-yk/weather-pattern-classification-data` に**2000-01-01〜2022-09-30の天気図が
既にある**(国会図書館版)。ERA5も同期間ダウンロード可能。**必要なのはラベルだけ。**
23年分あれば希少ラベルも10倍前後になる。

## 再現に使うコマンド

```bash
# 学習の前に。設定の不備を数秒で洗い出す
python -m scripts.preflight --data-dir <画像> --labels data/labels_v2.csv \
    --years 2023 2024 2025

# 天気図
python -m scripts.cross_validate --data-dir <画像> --labels data/labels_v2.csv \
    --years 2023 2024 2025 --out-dir runs/v2_chart

# ERA5格子
python -m scripts.cross_validate --input-mode era5-grid --arch small_cnn --coordconv \
    --labels data/labels_v2.csv --years 2023 2024 2025 --out-dir runs/v2_grid

# 比較(ラベルを絞って平均を取り直せる。基準も同じラベルで取り直される)
python -m scripts.compare_runs runs/v2_chart runs/v2_grid \
    --exclude front_passage stationary_front

# 混合(学習済みの重みを使う。再学習は不要)
python -m scripts.ensemble_chart_grid --data-dir <画像> --labels data/labels_v2.csv \
    --chart-weights runs/v2_chart --grid-weights runs/v2_grid \
    --years 2023 2024 2025 --out runs/v2_ensemble.json
```

`summary.json` には実行時の設定が記録される(それ以前の結果には無いので、
`compare_runs` は「設定の記録なし」と表示する)。各foldの学習経過は
`<重み>.history.json` に残る。
