# 物体検出を経由する気圧配置分類 — 計画と引き継ぎ

2026-08-26

天気図から直接10ラベルを当てる今の方式に対し、H/L/前線をいったん検出してから
その位置関係で気圧配置を判断する方式を試す。**この文書は別セッションで着手する
ための引き継ぎ資料**であり、計画本体(次節)と、既に分かっていること・
繰り返してはいけないこと(その後)からなる。

---

## 計画(原案)

### 背景

現在は天気図画像をCNN(EfficientNet)へ入力し、10種類の気圧配置を直接分類している。
しかし教師データは最終ラベルのみであり、「なぜその判断になったか」は学習していない。

予報官は実際には、

1. 高気圧中心を探す
2. 低気圧中心を探す
3. 前線を探す
4. 位置関係を確認する
5. 気圧配置を判断する

という手順を取る。そこで、高気圧・低気圧・前線などの中間概念を学習させ、
その結果を用いて最終的な気圧配置を分類する手法を試したい。

### 研究仮説

```
現状                 提案
天気図               天気図
 ↓                    ↓
CNN                  物体検出(H, L, T, 前線)
 ↓                    ↓
気圧配置              位置情報・構造情報
                      ↓
                     気圧配置分類
```

期待するもの: 説明可能性の向上 / 位置依存ラベルの改善 / 地域別分類への発展。

### Phase 1 高低気圧検出

天気図から高気圧・低気圧中心を検出する。対象は H(高気圧) / L(低気圧) /
T(台風) / TD(熱帯低気圧)。候補モデルは YOLOv11。まず300枚程度で試験実施。
成功条件は高い検出率(mAP)。

### Phase 2 前線検出

寒冷前線・温暖前線・停滞前線・閉塞前線を検出する。候補は YOLO Segmentation。
前線は細長いため、矩形検出よりセグメンテーションが適している。

### Phase 3 特徴量生成

物体検出結果から特徴量を作る。高気圧数 / 低気圧数 / 高低気圧の位置 /
高低気圧間距離 / 前線本数 / 前線長 / 地域ごとの高低気圧存在有無 など。

### Phase 4 気圧配置分類

Phase 3の特徴量を入力に、10ラベルを出力する。候補は XGBoost / LightGBM / MLP。
第一候補は XGBoost(データ量が少なくても安定し、特徴量重要度を確認できる)。

### 将来的な発展

地域別分類。同じ天気図でも「北海道→オホーツク海高気圧、関東→停滞前線、
沖縄→台風」のように、指定した地域に最も影響する気圧配置を返す。

### 補足

二つ玉低気圧は「低気圧が2つ存在する」という構造そのものなので、物体検出との
相性が良い。一方、西高東低は高気圧位置・低気圧位置・等圧線の向き・等圧線密度
など複数要素で決まるため、物体検出結果から特徴量を作って判定する。

目的は「CNNのブラックボックス判定」ではなく、予報官が何を見てどう判断したかを
AIに学習させることである。

---

## 引き継ぎ: 既に分かっていること

### この計画が効きそうな根拠(測定済み)

**CNNは位置を使っていない。** `scripts/attention_check.py` で、Grad-CAMの熱が
ラベルごとの「見るべき領域」(`data/regions.csv`)にどれだけ入っているかを測った
(指標の定義は `docs/2026-08-25-attention-regions.md`)。

オホーツク海高気圧は、記録が本当にオホーツク海高気圧の58枚に対してすら
lift 1.24・peak的中率 8.6%。**正解のときですらオホーツク海を見ていない。**
物体検出で中心座標を明示的に取れば、位置は構造的に手に入る。

**二つ玉低気圧が狙い目。** 交差検証のF1が 0.505 で、オホーツク海高気圧に次いで
低い。定義が文字通り「低気圧が2つ」なので、検出器には数えるだけの問題になる。
早い段階で分かりやすい成果が出る可能性が高い。

### 繰り返してはいけないこと

オホーツク海高気圧について、**3つの説明が実験で否定済み**。再検証は不要。

| 説明 | 検証方法 | 結果 |
|---|---|---|
| 確信度の較正のずれ | ラベルごとのPlattスケーリング | × ECEは0.116→0.036に直ったが成績は不変 |
| ラベルの取りこぼし | 誤検出9件を人が採点 | × 妥当なものは0件(太平洋高気圧型は30件中14件が妥当) |
| 位置情報の欠如 | CoordConvで学習・注目位置を測定 | × 見る場所が変わらず、F1も 0.326→0.270 |

詳細は `docs/2026-08-25-label-undercount.md`、`docs/2026-08-25-attention-regions.md`。

### 比較のときに守ること

**ラベルを変えたあとの結果は、変える前の結果と比べられない。**
台風ラベルをベストトラックから付け直したあと、付け直す前の実行と並べて
「+0.192の改善」と読んでしまった事故がある(`docs/2026-08-26-stale-run-comparisons.md`)。

- `scripts/compare_runs.py` は foldごとの陽性件数が食い違えば比較を拒否する
- `scripts/cross_validate.py` は `summary.json` にラベルファイルの指紋を記録する
- 過去の `runs/*/summary.json` は全て削除済み(現在のラベルと一致するものが無かった)

**Phase 4 の出力は今と同じ10ラベル**なので、既存CNNとは競合手法の関係になる。
優劣の判断には、同じfold・同じラベル・同じ評価コードを使うこと。
`src/split.py`(LOYO・`gap_days` によるリーク防止)と `src/evaluate.py`
(しきい値最適化)をそのまま通す。

### 再利用できるもの

| ファイル | 用途 |
|---|---|
| `scripts/preprocess_jma.py` | 天気図のトリミング・スタンプ消し |
| `scripts/collect_jma.py` / `fetch_and_predict.py` | 画像の取得(日付を指定するだけ) |
| `src/split.py` | LOYO分割・時間的リーク防止 — Phase 4 で必須 |
| `src/evaluate.py` | しきい値最適化つき評価 — 比較のために必須 |
| `src/calibration.py` | 確信度の校正(XGBoostでも同じ問題が出る) |
| `src/labels.py` / `data/labels_v2.csv` | Phase 4 の教師データそのもの |
| `src/regions.py` | **Phase 3 の「地域ごとの高低気圧存在有無」に直接使える** |
| `scripts/cross_validate.py` / `compare_runs.py` | 取り違え検出つきの交差検証・比較 |

`src/regions.py` はラベルごとの領域を天気図上の相対座標で持っている。
検出した中心の座標に対して `region.contains(x, y)` を呼ぶだけで、
「この高気圧はオホーツク海にあるか」という特徴量が作れる。

## 着手前に1時間で試すこと

**300枚のアノテーションを始める前に、機械的に抽出できないかを確かめる。**

気象庁の天気図は配色が固定されている(`scripts/collect_jma.py` 冒頭)。

> 海岸線・経緯度線=赤茶色、等圧線=黒、温暖前線=赤、寒冷前線=青、閉塞前線=ピンク

- **前線(Phase 2)**: 色でマスクを作れば、アノテーションなしで前線の画素が取れる
  可能性がある。赤・青・ピンク・赤青交互を分ければ種別まで付く。
  YOLO Segmentation を学習させる前にこれを試す。
- **H / L / T / TD(Phase 1)**: 同じフォント・同じ大きさで機械的に描画された記号。
  テンプレートマッチング(`cv2.matchTemplate`)で見つかる可能性がある。
  中心の「×」印も同様。

うまくいけば Phase 1・2 の手作業がほぼ不要になり、少なくとも自動抽出の結果を
YOLOの教師データの下地にできる。失敗しても1時間の損失で、YOLOに進むだけ。

**実施済み(2026-08-26)。結果は `docs/2026-08-26-detection-prescreen.md`。**
前線は学習ゼロで停滞前線を AUC 0.923 で分離でき、**Phase 2 の
アノテーションは要らない**。記号は連結成分では取れないが(太い等圧線と
繋がる)、人が数個切り出したテンプレートを回しながら当てれば1枚あたり
6.7個で、**Phase 1 も300枚のアノテーションは要らない**。

ただし台風は "T" とは書かれない。中心は丸で囲んだ×で、名前は
`STS 2405 MARIA` のような別フォントである。Phase 1 の対象を
「H / L / T / TD」としていた前提は成り立たない。

**注意**: 2000〜2022年の手動アーカイブ(国会図書館由来のスキャンJPEG)と、
2022-10以降の気象庁PDF由来のものでは画質が違う。色抽出はPDF由来のもので
先に試すこと。
