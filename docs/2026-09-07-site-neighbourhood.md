# 指定した地点の周辺だけを見る

2026-09-07

## きっかけ

小松のおろし風167日の検証で、誤り62件のうち**17件が「小松と無関係な特徴に
反応した事例」**だった。モデルは日本全体の天気図を見て判断するので、その地点に
影響しない遠方の気圧配置まで拾ってしまう。

これを「そう見える」ではなく**数字で言えるように**した。

## やったこと

天気図上に「地点とその周辺」を円1つで定義し、検出した高気圧・低気圧を
その円の中だけに絞り込めるようにした。

    src/sites.py            Site(中心・半径)と絞り込み
    data/sites.csv          地点の定義
    scripts/site_preview.py 円を天気図に重ねて目視確認する
    scripts/site_report.py  日付の一覧に対して周辺の系を数える

**学習し直しを伴わない。**検出結果を距離で絞り込んで数えるだけなので、
macro F1 0.669 も1位正解率83.4%も動かない。新しい分類器ではなく、
考察③(地点特有の現象への適用における課題)の裏付けを、推測から実測に
変えるための道具である。

## 小松の位置をどう決めたか

| | 値 |
|---|---|
| 中心 | (0.53, 0.55) 相対座標 |
| 半径 | 0.12(天気図の幅を経度約40度と見て、北緯36度付近で約430km) |

**緯度経度(北緯36.382/東経136.435)からは変換していない。**この天気図は
正距円筒図法ではなく、前処理の `autocrop_to_content()` が白縁を落とすため
画素と緯度経度の対応表も無い。過去に経緯線の目盛りから線形の式を作ったとき、
**東京が本州北部に、ソウルが満州に載った**(`docs/2026-08-25-attention-regions.md`)。

そこで `site_preview.py --grid` で相対座標の目盛りを天気図に重ね、地図の上で
直接読み取って決めた。決めるまでに2回直している。

    (0.50, 0.57)  中国地方あたりに載っていた   -> 北東へ
    (0.55, 0.53)  北東へ寄せすぎた             -> 南西へ
    (0.53, 0.55)  これで確定。半径も0.08から0.12へ広げた

`src/regions.py` の `Region` を使わなかったのは、あれがラベルごとの領域で、
名前が `src/labels.py` の LABELS に無いと例外になるため。地点は利用者が
決めるものなので別に用意した。形も矩形ではなく円にしてある。「地点から
○○以内」という言い方にそのまま対応するのと、矩形だと角が斜めに1.4倍
遠くまで入ってしまうため。

## 使い方

    # 1. 位置を目で確かめる(**これを飛ばすと以降は別の場所を測ったものになる**)
    python -m scripts.site_preview --site komatsu --date 2023-01-01 --grid --detect

    # 2. 日付の一覧に対して周辺の系を数える
    python -m scripts.site_report --site komatsu ^
        --dates-csv <おろし風の日付CSV> --date-column 発生日 ^
        --join <判定結果のCSV> ^
        --out reports\komatsu_nearby.csv --workers 4

## 読むときの注意

### 「周辺に系が無い」は「誤り」ではない(2026-09-07 追記・重要)

最初この文書には「全体は取れているのに周辺が0なら『遠くを見ていた』と読める」
と書いていた。**これは誤りだった。**利用者が 2011-02-01 を目で確かめて分かった。

その日は冬型で、全体では高2・低3を検出しているのに周辺は0だった。しかし
**冬型は西の高気圧と東の低気圧の配置で決まる気圧配置**なので、小松の近くに
あるのは混んだ等圧線であって中心ではない。中心はシベリアと東海上にある。
つまり**周辺が0なのが正常**で、モデルが間違えたわけではない。

同じことが前線通過・停滞前線にも当てはまる。前線は中心ではないので、
どれだけ正しく判定していても周辺の高低気圧は0になる。

そこで、ラベルごとに読み分ける必要がある。

| | 周辺に中心が無いのが自然 | 周辺に中心があるはず |
|---|---|---|
| 例 | 西高東低、前線通過、停滞前線、太平洋高気圧型、オホーツク海高気圧 | 日本海低気圧、二つ玉低気圧、移動性高気圧、南岸低気圧、台風 |
| 周辺0のとき | 正常 | 要確認 |

`site_report.py` は `--join` でラベルを渡すと**ラベル別の内訳**を出す。
「周辺に系なし」が冬型に偏っているなら当たり前の結果であり、日本海低気圧に
偏っているなら本当に怪しい。

**上の振り分けは気象の判断なので、利用者の確認を経てから固定すること。**

### 検出漏れの可能性

現状の検出には取りこぼしがある。だから `site_report.py` は周辺の個数だけで
なく**全体の個数も並べて出す**。両方0なら検出そのものを疑う。

発表では、この取りこぼしを隠さずに「周辺に系が無いと出た日には検出漏れも
含まれる」と添えるほうが説明として強い。
