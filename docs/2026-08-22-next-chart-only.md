# 天気図画像だけで成績を上げる — 提案(2026-08-22)

ERA5を入力から外した(`docs/2026-08-21-chart-vs-era5-grid.md` の決定)あとの計画。
効果の見込みが大きい順に並べる。上の3つで大半が決まると考えている。

現状: macro F1 0.636(`runs/v2_chart_spread`、LOYO 2023-25、trivial baseline 0.267)。

| ラベル | 件数 | 天気図F1 | 人間の再現性(F1) |
|---|---|---|---|
| 移動性高気圧 | 891 | 高 | 未測定 |
| 停滞前線 | 665 | 0.803 | 0.979 |
| 日本海低気圧 | 369 | 中 | 未測定 |
| 前線通過 | 340 | 中 | 未測定 |
| 西高東低 | 312 | 高 | 未測定 |
| 台風 | 247 | 高 | 0.571 → 機械化済み |
| 太平洋高気圧型 | 246 | 中 | 未測定 |
| 南岸低気圧 | 217 | 中 | 未測定 |
| オホーツク海高気圧 | 188 | 0.318 | **0.500** |
| 二つ玉低気圧 | 97 | 低 | 未測定 |

## 1. ラベルの上限を測り、定義を固める (最優先・最安)

**理由**: オホーツク海高気圧は人間が自分と F1 0.500 しか一致しない。モデルの
0.318 は「性能不足」ではなく天井に近い。一方で停滞前線は人間 0.979 に対して
モデル 0.803 で、まだ 0.176 の伸びしろがある。**この2つを同じ「0.3」「0.8」として
扱っている限り、どこに労力を割くべきか決められない。**

**やること**: 未測定の8ラベルについて、1ラベルあたり1か月分(60枚・10分程度)を
`scripts/review_cli.py` で盲検判定し、`scripts/compare_review.py` でκとF1を出す。
合計でも1.5時間ほど。そのうえで:

- 人間の再現性が低いラベル → 台風でベストトラックを使ったのと同じく、
  緯度経度の箱と閾値で機械的に決める。決めた基準は `src/labels.py` に書く。
- 再現性が高くモデルが低いラベル → ここが本当の改善対象。

**報告にも効く**: 各ラベルの数値に人間の上限を併記できると、「0.3で低い」ではなく
「上限0.5に対して0.32」と言える。

## 2. 時間方向を入れる (実装が小さく、効果の見込みが大きい)

**理由**: いまは1枚の天気図から判定している。しかし**前線通過**は定義からして
時間変化であり、静止画1枚では原理的に判別しきれない。**移動性高気圧**も
「移動性」が名前に入っている。人間は前後の天気図を見て判断している。

**やること**: 入力を 24時間前・当日 の2枚(あるいは -24h/-12h/0h の3枚)にする。
画像を横に並べるのではなく、チャンネル方向に重ねてEfficientNetの第1層だけ
差し替える(`src/model.py` の `_adapt_first_conv` がすでにこれをやっている。
ERA5格子用に書いたものが、そのまま使える)。

**注意**: 12Zの天気図も取得できるので枚数は増やせるが、**リークに注意**。
LOYO分割はテスト年から3日以内の学習データを除外している。前後の天気図を
入力に含めるなら、この除外幅を入力が参照する時間幅の分だけ広げること。

## 3. 2000〜2022年を追加する (最大の効果・最大の労力)

**理由**: 二つ玉低気圧97件・オホーツク海高気圧188件という少なさが、そのまま
F1 に出ている。データ量が最大の制約であることは疑いない。天気図15,522枚は
`jpeg-data` ブランチに取得済み。

**やること**: ただし15,522枚を順番に人手でラベリングするのは非現実的
(1枚10秒でも43時間)。次の順で労力を減らす:

1. **1を先に済ませる**。定義が固まる前に付けたラベルは、後で全部やり直しになる。
2. **機械で決まるものは機械で**。台風はベストトラックから全期間ぶん自動生成できる
   (`scripts/typhoon_from_besttrack.py`)。西高東低のような気圧配置も、
   定義さえ書ければ自動化の候補になる。
3. **残りは能動学習で順番を決める**。現行モデルで15,522枚を推論し、
   (a) 確信度が0.5付近で迷っている枚、(b) 希少ラベルの確率が高い枚 を優先して
   人間に見せる。全部を見ずに、効く枚から埋める。二つ玉低気圧を97件から
   300件にするのに、15,522枚を全部見る必要はない。

## 4. 天気図で自己教師あり事前学習 (2と3の間を埋める)

**理由**: いまの事前学習はImageNet(自然画像)で、天気図とはかけ離れている。
一方、**ラベルの付いていない天気図が15,522枚ある**。ラベル無しで使える。

**やること**: 15,522枚でSimCLRかMAEを回して重みを作り、そこから微調整する。
3のラベリングが終わる前に着手できるのが利点。ただし1〜3より不確実性は高い。

## 5. 細かい積み上げ (ほぼ無料だが小さい)

- **入力解像度 224 → 384**。前線記号や小さな低気圧記号が224で潰れている可能性。
  1回の交差検証で確かめられる。
- **推論時拡張(TTA)と複数シードの平均**。fold間の標準偏差 0.022 を下げる。
  左右反転は使わないこと(西高東低が東高西低になる)。
- **希少ラベルの重み付け**。二つ玉低気圧97件に対する損失の重みを上げる。

## やらないと決めたこと

- ERA5を入力に使う(3通り試して天気図に届かなかった。上記の決定を参照)
- ERA5のチャンネル追加(500hPa高度・風・相当温位)。ERA5を使わないなら意味がない

なお、ERA5を**ラベルを作る道具**として使うことは、上の決定と矛盾しない
(台風のベストトラックと同じ立場)。ただしそのラベルでERA5モデルを評価しては
いけない — 自分の入力の関数を再現するだけになる。いまはERA5モデル自体を
使わないので、この危険は消えている。
