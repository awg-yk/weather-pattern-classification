# 検出した特徴量による分類と、既存CNNの比較

2026-08-27

`docs/2026-08-26-detection-plan.md` の Phase 3・4 を一度通した結果。
天気図から記号と前線を検出し、38個の特徴量に変え、木のモデルで10ラベルを
分類した。同じfold・同じラベル・同じ評価コードで既存CNNと比べている。

---

## 結論

**全体では負けた。ただし計画の中心にある仮説は支持された。**

| | macro F1 | foldごと |
|---|---|---|
| `cv_baseline` (CNN) | **0.641** | 0.654, 0.628, 0.642 |
| `cv_features` (検出+木) | 0.404 | 0.405, 0.400, 0.408 |

差 -0.237、全foldで同符号。**偶然ではない。**

|---|---|---|---|
| **オホーツク海高気圧** | 0.299 | **0.499** | **+0.200** |
| 移動性高気圧 | 0.726 | 0.686 | -0.040 |

| 太平洋高気圧型 | 0.521 | 0.293 | -0.228 |

## オホーツク海高気圧が上がった(+0.200)

**これが計画の主題だった。**計画は次のように書いていた。

> オホーツク海高気圧は、記録が本当にオホーツク海高気圧の58枚に対してすら
> lift 1.24・peak的中率 8.6%。**正解のときですらオホーツク海を見ていない。**
> 物体検出で中心座標を明示的に取れば、位置は構造的に手に入る。

位置を明示的に与えたら 0.299 から 0.499 に上がった。**10ラベルのうち唯一、
CNNを上回った。**しかもCNNが最も苦手としていたラベルである。

計画は「位置情報の欠如」という説明をCoordConvで試して否定していた
(F1 0.326→0.270)。CoordConvは座標を入力に足すだけで、**どこに高気圧が
あるか**は教えない。検出は教える。同じ「位置情報」でも中身が違ったこと
になる。

## 二つ玉低気圧が下がった(-0.340)

**計画の予測が外れた。**計画は狙い目としてこう書いていた。

> 二つ玉低気圧が狙い目。交差検証のF1が 0.505 で、オホーツク海高気圧に次いで
> 低い。定義が文字通り「低気圧が2つ」なので、検出器には数えるだけの問題に
> なる。早い段階で分かりやすい成果が出る可能性が高い。

そうならなかった。考えられる理由:

- **検出が1枚あたり4個前後の低気圧を出す**(`docs/2026-08-26-detection-prescreen.md`)。
  常に3〜5個出るなら「2個」は区別にならず、数は検出の揺れに埋もれる
- 二つ玉は「2つある」だけでなく**日本海側と太平洋側に1つずつ**という配置で
  ある。`src/labels.py` の規約でも japan_sea_low と nankigan_low を置き換える
  関係にあり、数ではなく位置の組み合わせが定義に近い
- `low_spread`(最も離れた2つの距離)を入れたが、これも配置までは表さない

`scripts/feature_report.py` で、`n_low` と `low_spread` が実際にどれだけ
二つ玉を分けているかを測れる。**分けられていないなら分類器を変えても
上がらない。**

## 台風が下がった(-0.702)

**予想どおり。**台風には H/L の文字が無い。中心は丸で囲んだ×で、名前は
`STS 2405 MARIA` という別フォントである
(`docs/2026-08-26-detection-prescreen.md`)。今の特徴量には台風の手がかりが
ほとんど無いので、0.177 は「信号が無い」ことの表れであって、方式の限界では
ない。**中心の印を入れれば変わる見込みが高い。**

## 停滞前線が下がった(-0.270)のは意外

下見では、停滞前線ラベルを停滞pxだけで **AUC 0.923** で分けられていた。
それが 0.516 に留まっている。AUCは順位だけを見る目安で、しきい値も
交差検証も通していない数字だったので、そのまま成績にはならない。
ただし0.923と0.516の開きは大きく、**下見のAUCを成績の予測に使えないことの
実例**として記録しておく。

---

## 次にやること

1. **`scripts/feature_report.py` を走らせる。**どのラベルにどの特徴量が
   効いているかをAUCで出す。二つ玉が落ちた理由がここで分かる。
   手がかりが無いラベルは、分類器を変えても上がらない
2. **中心の印(×・丸で囲んだ×)を入れる。**台風・TDの手がかりになり、
   位置の精度も上がる。`build_features --marks` で渡せる
3. **等圧線の向きと密度を足す。**計画が西高東低の判定に挙げていたが、
   今の検出には入っていない。西高東低は -0.300 で、影響が大きいラベルである

## この結果の読み方

**「CNNのほうが良いので物体検出は筋が悪い」と読んではいけない。**

比べているのは、CNNが2432枚を丸ごと学習した結果と、**38個の手作りの
特徴量**である。特徴量には等圧線の情報が一切入っておらず、台風の手がかりも
無い。その状態で、CNNが最も苦手なラベルを +0.200 上回った。

計画の目的は「CNNのブラックボックス判定ではなく、予報官が何を見てどう
判断したかをAIに学習させること」だった。**オホーツク海高気圧の +0.200 は、
その方向に効くという最初の実測値である。**
