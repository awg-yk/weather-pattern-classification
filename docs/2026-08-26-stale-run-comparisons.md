# 古い交差検証の結果を削除した

2026-08-26

## 何が起きたか

CoordConvの効果を測るため、新しく回した3fold交差検証(`runs/cv_coordconv`)を
`runs/loyo_v2` と並べたところ、台風のF1が 0.703 → 0.895 (+0.192) と出た。
単一foldでも +0.17 が出ていたので、再現したと判断した。

**これは誤りだった。** 台風ラベルはこの間にベストトラックから機械的に
付け直されており、陽性が219件から247件に増え、fold内の分布も動いていた。

| | 2023年 | 2024年 | 2025年 | 計 |
|---|---|---|---|---|
| `loyo_v2` の台風support | 98 | 62 | 59 | 219 |
| 現在の台風support | 78 | 84 | 85 | 247 |

差はモデルではなくラベルのものだった。同じ罠に、この研究では以前も
「古いラベルファイルが残っていて1日無駄になる」形で嵌っている。

## 調べたこと

保存済み23件すべてについて、foldごとの陽性件数を現在のラベルと突き合わせた。

```
curve                 5fold → 比較不可
loyo_chart_ap         JSONが壊れている(文字コード不正)
loyo_v2               5/10ラベルのみ一致
loyo_v1_on_v2         5/10ラベルのみ一致
その他19件             4/10ラベルのみ一致
```

**現在のラベルと全ラベルが一致する実行は1つも無かった。** つまり残っていた
`summary.json` の実質的な役割は、比較相手として使われて誤った結論を出すこと
だけになっていた。

## やったこと

1. `runs/*/summary.json` を削除した(下に数値を残す)。
2. `scripts/compare_runs.py` が、ラベルの食い違う実行どうしの比較を拒否するようにした。
   foldごとの陽性件数を突き合わせ、違えば止める。ラベルファイルの記録が無い
   時期の結果でも、後から機械的に判定できる。承知のうえなら `--force`。
3. `scripts/cross_validate.py` が `summary.json` にラベルファイルの指紋
   (SHA-256の先頭16桁)とパスを記録するようにした。`src/calibration.py` に
   既にあった仕組みを流用している。陽性の枚数を変えずに中身を差し替えた修正は
   supportでは見抜けないので、指紋も併せて見る。

削除しただけでは再発を防げない。2と3が本体で、1はその結果として不要になった
ものの片付けにあたる。

## 取り消した記述

`docs/2026-08-25-attention-regions.md` に「過去の交差検証には、CoordConvが
オホーツク海高気圧のF1をおよそ2倍にした記録が残っている
(`runs/loyo_grid_small` 0.121 → `runs/loyo_grid_small_cc` 0.250)」と書いていた。

現在の入力(天気図)で直接確かめたところ、CoordConvはオホーツク海高気圧を
改善しなかった**(3fold・同一ラベルで 0.326 → 0.270)。当該箇所は差し替えた。
