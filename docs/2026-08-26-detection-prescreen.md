## 何を作ったか

`src/chartsymbols.py` に、色マスクと記号拾いをまとめた。

| 関数 | すること |
|---|---|
| `color_masks` | 温暖/寒冷/閉塞前線・海岸線・等圧線のHSVマスク |
| `band_overlap` | 色の帯どうしが同じ画素を取り合っている数。**成否の指標** |
| `segments` | マスクを連結成分に分け、長さと細長さを測る |
| `stationary_mask` | 赤と青が交互に並ぶ区間(停滞前線)を取る |
| `glyph_candidates` | テンプレート無しで、記号になりうる小さな孤立した黒い塊を拾う |
| `match_templates` | テンプレートを当て、重なりを抑えて位置を返す |
| `dominant_colors` | 画像に多い色とHSV。閾値を決めるための実測用 |

位置は `src/regions.py` と同じ相対座標(0〜1)で返す。検出した中心をそのまま
`region.contains(x, y)` に渡せば Phase 3 の特徴量になる。

### 等圧線は大きさで落ちる

記号拾いはテンプレートを要らないところから始める。等圧線は図の端から端まで
繋がった**1つの巨大な連結成分**になるので、bboxの一辺で足切りするだけで落ちる。
残るのは記号(H/L/T/TD・×)と、気圧の数値・緯度経度の目盛といった文字。
この段階では両者を区別しない。**1枚あたりの候補数**が、テンプレートマッチング
が現実的かどうかの目安になる。数十個なら選り分けられる。数百個なら苦しい。

## 合成天気図で分かったこと

本物が無いので、気象庁の配色どおりに描いた合成天気図で確かめた。
**確かめたのはコードが仕様どおり動くことだけで、本物で前線が取れるかではない。**
合成天気図は自分で描いたものなので、色が分かれるのは当たり前である。

それでも、本物でも起きる性質のことが2つ出た。

**色の線が等圧線を上書きすると、切れた等圧線の断片が候補に混じる。**
合成天気図では海岸線が等圧線を横切り、その左側に短い切れ端が4つ残って、
記号2つに対し候補6つになった。記号候補拾いは「記号だけを拾う」ものではなく、
「テンプレートを当てる先を数十個に絞る」ものだと考えるのが正しい。

**記号どうしは入れ子になる。** "H" の右の縦棒は "L" によく似る。一致スコアの
閾値を0.7にすると、Hの中にLが誤検出された。天気図では "TD" の中に "T" が
あるので同じことが起きる。対策を2つ入れた:

- 重なりの抑制を IoU ではなく「小さいほうの面積に対する重なり」で測る。
  入れ子は IoU では小さく出るため、IoU では内側の誤検出が生き残る。
- 既定の一致スコアを 0.8 にした。誤検出はまずこちらで消える。

## 走らせ方(天気図のある環境で)

```powershell
# 0. 天気図を用意する(2022-10以降の気象庁PDF版から先に試すこと)
python -m scripts.collect_jma --start 2024-07-01 --end 2024-07-31 --out data/raw/jma
python -m scripts.preprocess_jma --in-dir data/raw/jma/png --out-dir data/processed/jma

# 1. まず色を測る。閾値をいじるのはこの後
python -m scripts.chart_palette --in-dir data/processed/jma --limit 8

# 2. 前線(Phase 2)
python -m scripts.extract_fronts --in-dir data/processed/jma --limit 20 `
    --overlay reports/fronts --labels data/labels_v2.csv

# 3. 記号(Phase 1)。まず候補の規模を見る
python -m scripts.extract_symbols scan --in-dir data/processed/jma --limit 20 `
    --overlay reports/symbols

# 4. reports/symbols の箱の番号を見て、Hの候補からテンプレートを作って当てる
python -m scripts.extract_symbols cut --image data/processed/jma/Js_2024070100.png `
    --index 7 --name H --out data/templates
python -m scripts.extract_symbols match --in-dir data/processed/jma `
    --templates data/templates --limit 20 --overlay reports/symbols
```

**閾値をいじる前に必ず1を走らせること。** `src/chartsymbols.py` の
`DEFAULT_BANDS` は仕様から起こした暫定値で、実測値ではない。

## 何を見て決めるか

数字だけでは決まらない。`--overlay` の重ね描きを必ず目で見ること。

### 前線 (Phase 2)

| | 合格 | 不合格 |
|---|---|---|
| 海岸線の混入 | `band_overlap` の coastline×warm_front がほぼ0 | 無視できない数が出る |
| 前線の形 | 1本の前線がおおむね1〜3区間 | 10区間以上に割れる |
| ラベルとの一致 | `stationary_front` の日に停滞前線が出て、無い日に出ない | 相関しない |

**赤と赤茶色が分かれるかどうかがこの方式の成否を決める。**ここが駄目なら、
前線については色マスクを諦めて計画どおり YOLO Segmentation に行く。

### 記号 (Phase 1)

| | 合格 | 不合格 |
|---|---|---|
| 候補数 | 1枚あたり数十個 | 数百個 |
| 大きさの分布 | 特定の幅×高さに票が集まる(同じフォントで描かれている証拠) | ばらける |
| 検出数 | 1枚あたりH/Lが合わせて2〜6個 | 桁が違う |

候補の大きさがばらけるなら、前処理の拡大率が画像ごとに違うということなので、
テンプレートを大きさ違いで何枚か作るか、`preprocess_jma.py` を見直す。

## この方式が駄目でも残るもの

計画のとおり、失敗しても損失は小さい。自動抽出の結果は、そのまま YOLO の
教師データの下地に使える。人が0から300枚描くより、機械の出力を直すほうが速い。
