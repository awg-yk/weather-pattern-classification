# 物体検出の下見 ― 色とテンプレートで前線・記号が取れるか

2026-08-26

`docs/2026-08-26-detection-plan.md`「着手前に1時間で試すこと」に対する記録。
**300枚のアノテーションを始める前に、機械的に抽出できないか**を確かめた。

対象は気象庁PDF版(2022-10以降)。`data/labels_v2.csv` の2432件はすべてこの
時期なので、現行のラベル付きデータについては全域が対象になる。

## 結論

**両方とも取れる。YOLO は要らない。**

| | 結果 | アノテーション |
|---|---|---|
| **前線 (Phase 2)** | 学習ゼロで停滞前線を **AUC 0.923** で分離 | **不要** |
| **記号 (Phase 1)** | 人が12枚切り出したテンプレートで **6.7個/枚** | **不要**(手作業は数十分) |
| **配色** | 全色を実測。前線は純色、地図はくすんだ色 | ― |
| **位置** | 画像間のずれ **0.01画素** | ― |
| **台風** | H/L の文字が無い。中心は丸で囲んだ× | 別途要検討 |

計画は「うまくいけば Phase 1・2 の手作業がほぼ不要になり、失敗しても
YOLOの教師データの下地にできる」と書いていた。**前者になった。**

ただし当初の見立てとは道筋が変わった。**記号は連結成分では取れない。**
人が数個切り出したテンプレートを、回しながら当てる。

## 走らせ方

```powershell
.\setup-session.ps1          # $processed_dir が設定される
pip install opencv-python-headless

# 1. 色を測る(閾値をいじる前に必ずこれ)
python -m scripts.chart_palette --in-dir $processed_dir --limit 12

# 2. 前線

    --overlay reports\fronts --labels data\labels_v2.csv

# 4. 記号。テンプレートは data\templates\ に人が用意する(後述)

    --templates data\templates --limit 20 --threshold 0.65 `
    --angle-range 60 --overlay reports\symbols
```

前線もほとんど出ず、純赤が上位色に現れない。

## Phase 1 記号 ― 成立、ただし道筋が違う

### 連結成分では取れない

記号は塗りつぶしではなく**太い中抜きの文字**で、**等圧線がその上を横切る**。
細い等圧線は細らせれば消えるが、強調線(1000hPaなど)は太いので残り、記号と
繋がったままになる。繋がると図の端から端まで伸びる巨大な連結成分の一部に
なって落ちる。大きさの上限を広げても直らない。

実測では、切り出した6個中5個がこれに当たった。合成図での比較:

| 手法 | 太い等圧線が横切る図で(正解3個) |
|---|---|
| 連結成分 (`glyph_candidates`) | **0個** |
| テンプレート (`match_templates`) | **3個**(閾値0.8でも) |

`match_templates` は連結成分を使わず、マスクの上をテンプレートで走査する。
**記号を数個切り出せば、残りは全部見つかる。**

### テンプレートは人が作る

太い等圧線と記号の分離は「この形は文字だ」という判断であって、まさに
Phase 1 で YOLO を想定していた理由である。一方、人が画像編集ソフトで
切り出すのは短時間で済み、しかも確実である。等圧線を消せるし、重なって
いない個体を選べる。

| テンプレート | 1枚あたりの検出 | スコア中央値 |
|---|---|---|
| 機械で切り出し(見切れあり) | 5.3個 | 0.74 |
| 機械 + 余白35画素 | 3.4個 | ― |
| 機械 + 枠を自動調整 | 2.6個 | ― |
| 人が切り出し(H5・L3) | 6.3個 | 0.75 |
| **人が切り出し(H5・L7)** | **6.7個** | **0.75** |

目視で**高気圧はすべて検出できていた**。L には取りこぼしが残る。
テンプレート1枚あたりの増分は +2個弱まで落ちており、この方式の天井が近い。

### 効かせるのに必要だった3つ

どれを欠いても当たらない。

1. **回転** ― 同じ記号でも傾きが違う。回さないと切り出した本人しか
   当たらない(1枚あたり0.1個)。実測の傾きは -55度〜+60度、中央値 +10度
2. **5度刻み** ― 5度ずれるとスコアが0.72まで落ちる。10度刻みでは余裕が無い
3. **複数個体** ― 1個体では等圧線の重なり方が違うと外れる

### テンプレートの作り方

`data\templates\` に画像を置くだけ。`H.png` `H2.png` ... `L.png` `L2.png` ...
と名付ける。**末尾の数字は自動で H・L にまとめて数える**(`symbol_of()`)。

- png 以外(bmp/jpg/gif/tif)も読む
- 白地に黒の画像は自動で反転する
- 記号の割合が5%〜60%を外れたら指摘する
- **記号のまわりは切り詰める。**余白が大きいと当たりが悪くなる(実測)

`extract_symbols grid --image <天気図>` が座標のめもりを重ねた画像を出すので、
切り出す位置を読むのに使える。

## 台風

2024年8月11日の天気図で確認した。台風は H や L のような中抜き文字を
**持たない**。

| 要素 | 描かれ方 |
|---|---|
| 中心 | **丸で囲んだ×**。低気圧の中心と同じ記号 |
| 気圧の谷 | 同心円状に閉じた等圧線が何重にも |
| 名前 | `STS 2405 MARIA` という細い等幅の文字 |
| 気圧 | `980hPa` |
| 暴風域の円 | この日には無い |
| 熱帯低気圧 | `TD` の文字 + 丸囲みの× + 気圧値 |

計画は Phase 1 の対象を「H / L / T / TD」としていたが、**台風は "T" とは
書かれない**。TD だけは文字で書かれる。

### 中心の印が高低を区別している(仮説・未検証)

同じ天気図で、中心の印に2種類あることに気づいた。

| 印 | 付いていた場所 |
|---|---|
| **ただの ×** | 1008(H)、1020(H)、1020(H) |
| **丸で囲んだ×** | 1004(L)、996(L)、994(L)、台風、TD |

2024年7月1日でも2023年1月1日でも同じだった。**3枚見ただけの仮説である。**

正しければ H と L の文字を読む必要がない。中心の印が位置と種別の両方を持つ。
しかも×印は小さく丸い塊で、閉じた等圧線の内側にあり線と重なりにくい。
`cluster` の一覧にも×印と丸囲みの×が別々の山として出ていた(9個・3個・3個)ので、
**連結成分で素直に取れる**。台風を扱うならこちらが要る。

### 中心の印と H/L の両方を残す(判断)

中心の印が高低を区別しているなら、H/L の文字は要らないように見える。
しかし両方を残す。理由は3つ。

**×は中心そのもの、H/L は近くに置かれたラベルである。**実際の天気図でも
H や L は中心から離れた位置に描かれていた。Phase 3 で `region.contains()` に
渡すのは中心座標なので、**位置については×が構造的に正しい**。H/L の位置を
使うと、ラベルの置き方のぶんだけずれる。

**印の仮説は3枚しか見ていない。**「ただの×=高気圧、丸囲み=低気圧」が全期間で
成り立つ保証はない。また×は閉じた等圧線の内側にあるので、等圧線が閉じない
弱い低気圧では拾えない可能性がある。どちらも未確認で、破れたときの受け皿が要る。

**互いを検証できる。**2つが独立に「この日は高気圧2個・低気圧3個」と言うなら
両方とも正しい見込みが高く、食い違った枚数だけ人が見ればよい。
これは宿題の「記号の精度と再現率を分けて数える」を**正解ラベル無しで**
進める方法になる。20枚を1枚ずつ見るのは骨だが、食い違った数枚なら現実的である。
`scripts/compare_runs.py` が「foldごとの陽性件数が食い違えば比較を拒否する」
のと同じ考え方。

**主役は×、H/L は照合と受け皿**という位置づけにする。

確かめ方: ×と丸囲みの×のテンプレートを切り出して当て、丸囲みの×の数が低気圧の数と、
×の数が高気圧の数と一致するかを見る。印は回転しないので `--angle-range 20`
で足りる。

## 天気図は画素単位で揃っている(確認済み)

`scripts/check_alignment.py` で、海岸線マスクの位相相関からずれを測った。

| 対象 | 枚数 | 画像の大きさ | dxの幅 | dyの幅 |
|---|---|---|---|---|
| 2023年1月 | 30 | 1453x1500 | 0.02画素 | 0.01画素 |
| 2024年7月 | 20 | 1453x1499 | 0.01画素 | 0.03画素 |

**同じ大きさの画像どうしは0.01画素の精度で揃っている。**`src/regions.py` の
「全画像が同じ基準でトリミングされているので相対座標なら画像間で揃う」と
いう前提は、気象庁PDF版については成り立っている。Phase 3 で検出した中心
座標を `region.contains()` に渡してよい。

月をまたぐと画像の高さが1画素違う(1500対1499)。相対座標を使うかぎり実害は
無いが、位相相関は大きさの違う画像を比べられないので、一番多い大きさだけを
見ている。

なお `data/regions.csv` の矩形が**正しい海域を指しているか**は別の話で、
これは未確認のまま(`scripts/regions_preview.py` で重ねて見る)。

## 繰り返してはいけないこと

**この節がこの文書で一番役に立つ。**すべて実際にやって間違えたことである。

### 測り方の誤り

| 誤り | 何が起きたか | 正しい測り方 |
|---|---|---|
| 帯の重なりが0なら分離できている | **片方の帯が空でも0になる。**海岸線がまるごと温暖前線に入っていたのに重なりは0と出た | 画素数の変動(`band_variation`)と位置(`stability`)を併せて見る |
| 画素数が毎回同じなら地図の備品 | **等圧線も引っかかる。**常に図全体を覆うので総量が動かない | 位置を見る。海岸線は毎回同じ画素、等圧線は日ごとに動く |
| 毎回点灯した画素の割合で備品を判定 | **上書きで備品を取り逃がす。**等圧線が海岸線の上に描かれ、1枚あたり5.1%が隠れる。12枚で0.53まで落ちる | 点灯回数の**中央値**を使う。隠れは効かない |
| 最低スコアがしきい値に近ければ取りこぼし | **検出が増えれば必ず張り付く。**常に警告が出る | しきい値ぎわに何割溜まっているかを見る |
| 角度の範囲の端に1個でもあれば広げる | **検出が増えればほぼ必ず出る。**広げても結果は変わらなかった | まとまった数(3個以上かつ5%以上)が端にあるときだけ |
| 上限を変えた測定どうしを比べる | 候補の一辺の上限を48から64に変えたのに記録せず、1月と7月の結果を並べていた | 測定条件を毎回出力する |

### 見立ての誤り

**実物の天気図を見ずに推測して、2度外した。**

- 記号が黒の候補に出てこない → 「色付きだろう」と推測して色の帯を探す機能を
  作った。実際は黒の中抜き文字で、原因は大きさと合流だった
- テンプレートが見切れている → 「余白を足せばよい」と推測した。**かえって
  悪くなった**(5.3個/枚 → 3.4個)。増えた分の大半が周りの等圧線で、等圧線は
  場所ごとに違うため一致スコアを押し下げる

**天気図の画像を1枚見せてもらうたびに正解にたどり着いている。**
画素を推測で語らないこと。

### 道具の作りの誤り

- `cluster` が書き出す一覧 `clusters.png` を、テンプレートとして読もうと
  していた(名前が cluster で始まるため)
- 条件を変えて `cluster` を実行し直したとき、前回の山を消していなかった。
  `match` はディレクトリの中を全部読むので、条件の違う山が混ざったまま
  照合し、無効な結果を出していた
- 記号を等圧線から切り離せなかったとき、黙って別の枠を返していた。
  そのせいで「記号が見切れている」と誤報告した
- 日本語Windowsのコンソールは cp932 で、em-dash(U+2014)が出せない。
  表を出し終えた最後の1行で `UnicodeEncodeError` になった。
  `tests/test_chartsymbols.py` で縛ってある。**なお既存の `label_tool.py`・
  `predict_charts.py`・`gradcam_grid.py`・`gradcam_report.py`・
  `compare_review.py` にも同じ文字があり、同じ条件で落ちうる**(未着手)

- **中心の印(×と丸囲みの×)の仮説**を確かめる。正しければ H/L の文字が要らなくなり、

  **中心の印と H/L の答えを突き合わせ、食い違った枚数だけ人が見る**のが
